## The short debate

The prompt asked whether a project's README should present its quickstart or
architecture explanation first. The actual responses were:

**Quickstart first:**

> A runnable quickstart proves the tool works before asking readers to invest in understanding it, converting curiosity into a working install in under a minute. Architecture explanations only pay off once someone is already hooked, so leading with them risks losing skimmers who never reach the good part.

**Architecture first:**

> A brief architecture section orients readers before they run anything, so the quickstart's commands map onto a mental model instead of feeling like blind incantations. Skipping straight to commands invites cargo-culting and produces harder-to-diagnose "it didn't work" issues once the setup diverges from the happy path.

**Synthesis:**

> A quickstart-first README with a two-to-three-line "how it works" callout right above the commands is the practical middle ground: skimmers get a working install fast, but the brief framing keeps them from blind-copying commands they don't understand. Save the deeper architecture section for later in the doc.

Measured step timing relative to debate start:

| Step | Started | Finished |
| --- | --- | --- |
| Quickstart advocate | +0.004 s | +5.920 s |
| Architecture advocate | +0.015 s | +5.166 s |
| Synthesis | +5.922 s | +12.467 s |

Both advocates used separate calls to the same model with opposing role prompts.
This proves concurrent execution and context handoff; it does not establish
independence across model vendors. Use `--peer-model` to try that variation.

## Compatibility finding and limits

The first Codex attempt exposed an incompatible combination of `--sandbox` and
`--approve-for-me`. The branch now keeps explicit `workspace-write` confinement
and omits the conflicting approval shortcut; its argument regression test passes.

A second attempt found a local installation mismatch: the global npm Codex CLI
0.152.1 cannot parse the desktop app's newer feature configuration, while the
desktop native Codex 0.153.4 can. The shared user configuration was preserved.
The successful examples therefore used Claude. Updating the CLI selected by
PATH or adding an explicit executable selection/isolated-config feature is a
follow-up; this report does not claim a successful Codex inference run.

The refreshed bridge Codex catalog did not advertise Astra. Astra handled the
product implementation/review and Daybreak Blue handled security hardening;
those development models are distinct from the live demo model above.

This is local Windows validation. CI on the eventual pushed commit remains the
source of Linux and hosted security-check results. No release was cut.

## Reproduce

See [the walkthrough](../guides/pipelines.md) and the three JSON definitions in
[`examples/pipelines`](../../examples/pipelines).

```sh
node scripts/demo-pipelines.mjs --model cli-claude/claude-sonnet-5 --allow-write-demo --approve-demo
```

The script registers fresh demo pipeline, repository and workspace entries and
retains them for inspection. Results are saved in its printed scratch directory.
The model must be installed, authenticated and advertised by the local bridge.
