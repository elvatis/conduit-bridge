# 💡 Change and implementation requests

## 👋 Welcome!

We’re using Discussions as a place to connect with other members of our community. We hope that you:

- Ask questions you’re wondering about.
- Share ideas.
- Engage with other community members.
- Welcome others and are open-minded. Remember that this is a community we
  build together 💪.

To get started, comment below with an introduction of yourself and tell us about what you do with this community.

## 🛠️ Share a change or implementation request

Use this discussion to propose an improvement to Conduit. Ideas can cover a new provider, model, transport, API field, dashboard feature, workflow, documentation update, or another implementation detail.

Please search existing discussions first. One request per discussion makes it easier to compare ideas, ask follow-up questions, and track decisions.

Copy the template below when you open a request:

### Request

**Summary**

Describe the requested change in one or two sentences.

**Problem or use case**

What are you trying to do? Who would benefit? Include a concrete example when possible.

**Proposed behavior**

Describe how the feature should work from a user’s perspective. Include example commands, requests, responses, or screenshots when useful.

**Scope**

- [ ] Documentation only
- [ ] Dashboard or user interface
- [ ] API or protocol
- [ ] Provider, model, or transport
- [ ] Local runtime or storage
- [ ] Workflow, governance, or security

**Alternatives considered**

What workarounds or other designs have you tried?

**Compatibility and risks**

Could this affect existing clients, provider credentials, local data, performance, or security? Call out any migration or rollout concerns.

**Implementation context**

Link related issues, pull requests, documentation, examples, or a possible starting point. You do not need to have an implementation ready to start the discussion.

### Discussion guidelines

- Keep the request focused on one outcome.
- Explain the user need before prescribing an implementation.
- Share evidence, examples, and trade-offs.
- Treat alternative proposals as part of the design process.
- If the request becomes implementation-ready, maintainers may open or link an issue and pull request.
